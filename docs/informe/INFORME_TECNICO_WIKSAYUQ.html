WIKSAYUQ

Informe integral del sistema

Problema, objetivos, funcionamiento del código, requisitos funcionales y no funcionales, arquitectura, experiencia de usuario, paleta visual, capturas y wireframes.

Fecha de corte: 29 de julio de 2026

Conclusión ejecutiva. WIKSAYUQ es un MVP funcional centrado en la gestante. Permite acceso, seguimiento básico, calendario, historial, educación, contactos y operación offline parcial. Aún no está listo para producción clínica: el rol de personal de salud no tiene interfaz, SOS/autoevaluación no están integrados de extremo a extremo, la sincronización requiere idempotencia y faltan pruebas automatizadas.

1. Problema

Las gestantes de zonas altoandinas pueden enfrentar distancia geográfica, conectividad intermitente, barreras lingüísticas y fragmentación de la información prenatal. Esto dificulta recordar controles, reconocer signos de alarma, localizar atención y mantener continuidad entre la gestante y el establecimiento de salud. WIKSAYUQ busca concentrar ese acompañamiento en una aplicación móvil culturalmente contextualizada y capaz de degradarse cuando no hay Internet.

2. Objetivos

  • Desarrollar una aplicación móvil para el seguimiento prenatal de gestantes en zonas altoandinas del Perú.
  • Centralizar controles, citas, vacunas, peso e historial del embarazo.
  • Reducir barreras lingüísticas mediante español y Runasimi.
  • Mantener funciones esenciales cuando la conectividad es intermitente.
  • Detectar signos de alarma y facilitar el contacto con servicios de salud.
  • Preparar la coordinación futura entre gestante, personal de salud y administración.

3. Alcance y actores

Incluye: gestante, autenticación, embarazo, controles, citas, vacunas, calendario, historial, peso, educación, contactos, centros y almacenamiento offline parcial.

Fuera o parcial: personal de salud, administración, alertas operativas, exámenes, factores de riesgo, notificaciones push, auditoría y resolución de conflictos.

4. Arquitectura y funcionamiento del código

4.1 Inicio y navegación

  1. frontend/app/_layout.tsx inicializa SQLite y SyncService.
  2. NetInfo observa conectividad y sincroniza al volver Internet.
  3. frontend/app/index.tsx decide idioma, sesión y rol.
  4. Expo Router abre bienvenida, login o Inicio.
  5. La ruta de personal de salud aún no existe.

4.2 Autenticación

DNI y PIN se envían al backend; Prisma busca el perfil, bcrypt compara el hash y JWT firma la sesión. SecureStore protege el token en móvil y localStorage lo conserva en web. Faltan refresh, revocación y limpieza completa al cerrar sesión.

4.3 API y datos

Express aplica Helmet, CORS, parseo JSON, Morgan y rate limits. Los controladores usan Prisma contra PostgreSQL. El esquema reúne 34 modelos agrupados en identidad, embarazo, clínica, emergencia, mensajería, catálogos y operación.

4.4 Offline

saveOrQueue guarda PENDING local y encola. Al reconectar se realiza push y luego pull. Se debe eliminar la cola tras éxito inmediato y garantizar idempotencia por offline_id.

13. Requisitos de ejecución

  • Node.js 20.x, npm, Expo Go o emulador.
  • PostgreSQL/Supabase y variables de entorno.
  • PC y móvil en la misma WiFi para el despliegue local.
  • DATABASE_URL, DIRECT_URL, JWT y CORS en backend.
  • EXPO_PUBLIC_API_URL=http://IP_DEL_PC:3000/api en frontend.

Comandos: npm install, npm run dev --workspace=backend y npm run start --workspace=frontend.

17. Conclusión

WIKSAYUQ posee una base sólida para demostración y validación con gestantes: identidad cultural diferenciada, seguimiento prenatal básico y estrategia offline. Para convertirse en un sistema clínico confiable debe cerrar primero seguridad, funciones de emergencia, sincronización, personal de salud y pruebas. Este documento debe mantenerse como línea base: todo requisito nuevo deberá incluir responsable, prioridad, criterio de aceptación y evidencia de prueba.

Advertencia: Este sistema es un prototipo académico y no reemplaza la evaluación, diagnóstico o recomendación de un profesional de la salud.
